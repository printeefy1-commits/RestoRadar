# RestoRadar

أساس تطبيق محلي لإدارة إشغال طاولات المطعم وتنظيم مهام الفريق، بواجهة عربية تدعم الهاتف.

## المنفذ حاليًا

- حسابات منفصلة للمالك والمدير والنادل، مع صلاحيات يفرضها الخادم.
- طاولات وجلسات مؤقتاتها مشتقة من أوقات محفوظة في PostgreSQL.
- تصحيح إشغال يدوي بسبب إلزامي وحماية 60 ثانية، وتعديل أوقات الجلسة إلى الخلف بسجل تدقيق.
- تنبيهات مشتركة بإقرار ذري، وتعيين يدوي للمهام وإعادة إسنادها والقبول والإكمال.
- مهلات يُدخلها المالك دون قيم افتراضية؛ لكل محاولة إسناد نسخة من السياسة وقت تعيينها.
- فصل إكمال التنظيف عن تأكيد المدير للجاهزية.
- محاكاة صريحة لانتقالات متحقق منها؛ معطلة افتراضيًا ومحصورة بالمالك.
- اختبارات منطق وتكامل PostgreSQL ومتصفح بمقاس Android.
- تجربة فيديو مسجل للمالك، مع رفع MP4 من الموقع وحذف المقطع المرفوع أو استبداله، ورسم مناطق المقاعد وتصدير النتائج.

هذه نسخة تأسيسية وليست MVP v1 كاملًا. تتوفر [تجربة اختيارية لتحليل فيديو مسجل على CPU](docs/operations/recorded-video-trial.md)، مع مناطق مقاعد يحددها المالك وتقرير مستقل. **لا تتضمن بعد** كاميرات حية أو RTSP/ONVIF أو تفعيل خرائط المراقبة أو السحابة أو دفع الإشعارات أو تطبيق Android أصليًا. الواجهة تتحدث كل 3 ثوانٍ؛ WebSocket ودعم PWA القابل للتثبيت يأتيان لاحقًا.

## المتطلبات

Node.js 24، وnpm، وDocker مع Compose، أو PostgreSQL 17 متاح محليًا. يحتاج مستخدم الترحيل إمكانية تثبيت `btree_gist`. لا تستخدم بيانات قاعدة التطوير أدناه في الإنتاج.

كل مهمة سحابية معزولة أصلًا: استخدم المستودع الحالي ولا تنشئ Git worktree إضافيًا.

## تشغيل التطوير

نفّذ من جذر المستودع:

```bash
npm ci
docker compose -f infra/compose/compose.yml up -d --wait
# أنشئ .env فقط إن لم يكن موجودًا؛ لا تستبدل إعداداتك الحالية.
test -f .env || cp .env.example .env
npm run db:migrate
```

لإنشاء أول مالك مرة واحدة، اختر قيمك الخاصة. تُقرأ كلمة المرور دون عرضها، ولا تُكتب في الملف أو وسيطات الأمر:

```bash
export RESTAURANT_NAME='اسم المطعم'
export OWNER_NAME='اسم المالك'
export OWNER_EMAIL='your-email@example.com'
read -r -s -p 'كلمة مرور المالك (12 حرفًا على الأقل): ' OWNER_PASSWORD
export OWNER_PASSWORD
npm run setup:owner
unset OWNER_PASSWORD
```

لا توجد حسابات أو كلمات مرور تطبيق افتراضية. الحسابات التجريبية في الاختبارات معزولة وتُحذف بعد انتهاء الاختبار. كلمة مرور PostgreSQL في Compose مخصصة للتطوير على loopback فقط.

```bash
npm run dev
```

بعد تسجيل الدخول، افتح الإعدادات وأدخل مهلات القبول والإكمال للاستقبال والتنظيف، وأضف الطاولات وحسابات الفريق. جميع المهلات بالثواني من 1 إلى 86400، دون اقتراح أرقام تشغيلية معتمدة.

يمكن تفعيل `ENABLE_SIMULATOR=true` في `.env` وإعادة تشغيل الخادم للتجربة. زر المحاكاة يرسل حدثًا **متحققًا افتراضيًا** بمدة 5 أو 30 ثانية، ولا يشغّل نموذج رؤية. المغادرة المحاكية تتطلب أن تسمح أوقات الجلسة بعودة وقت المغادرة 30 ثانية إلى الخلف؛ يمكن استخدام تصحيح المدير للتجربة الفورية. لا تفعّل المحاكي عند ربط بيانات مطعم حقيقية.

## البناء والتشغيل

```bash
npm run build
npm start
```

الخادم يقدم الواجهة المبنية وAPI من المصدر نفسه. مسار فحص الجاهزية `/api/health` يتحقق من اتصال قاعدة البيانات. الخدمات الحية لا تبقى بعد استعادة آلة سحابية؛ يجب إعادة تشغيل PostgreSQL والخادم.

الإعداد الافتراضي يربط الخدمة محليًا فقط. قبل أي نشر شبكي: استخدم HTTPS ومصدرًا موثوقًا في `PUBLIC_ORIGIN` و`COOKIE_SECURE=true`، وأسرار قاعدة بيانات مستقلة، ودور تشغيل PostgreSQL محدود الصلاحيات ونسخًا احتياطية مجرّبة. لا تعرض منفذ قاعدة البيانات للعامة.

## الاختبارات

```bash
npm run check
export TEST_DATABASE_URL='postgres://restoradar:local-development-only@127.0.0.1:5432/restoradar'
npm run test:integration
npx playwright install --with-deps chromium
npm run test:e2e
```

اختبارات التكامل والمتصفح تنشئ مخططًا فريدًا لكل تشغيل وتحذف ذلك المخطط وحده، ولا تمس مخطط التطبيق. استخدم قاعدة تطوير أو اختبار. اختبارات المتصفح تبني الواجهة وتبدأ خادمًا بمنفذ مؤقت.

إذا كان Chromium مثبتًا مسبقًا، يمكن استخدامه دون تنزيل إضافي:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

في البيئات التي لا تسمح بكتابة cache داخل مجلد المستخدم، أضف `--cache /workspace/.npm-cache` إلى `npm ci`. اختبارات الهاتف تستخدم محاكاة متصفح؛ يلزم اختبار جهاز Android فعلي لاحقًا.

## البنية والتسليم التالي

للنشر التجريبي على AWS مباشرة من GitHub، راجع [خطوات إنشاء EC2 وجلب المستودع وتشغيل HTTPS](docs/operations/ec2-test-deployment.md). لا يتطلب هذا المسار تنزيل حزمة على جهازك أو رفعها إلى S3. لتفعيل تحليل الفيديو المسجل الموجود على الخادم، اتبع [دليل تجربة الفيديو](docs/operations/recorded-video-trial.md).

راجع [قرارات المنتج](docs/decisions/001-approved-baseline.md)، و[المعمارية](docs/architecture/foundation.md)، و[خطة التسليم](docs/implementation-plan.md).

تبقى `REQUIREMENTS.md` مرجع المتطلبات الأصلي؛ قرارات المالك اللاحقة مسجلة في وثيقة القرارات بدل تعديل الأصل.
