# الأساس التشغيلي

## حدود المكونات

- `packages/contracts`: عقود Zod وأنواع الحالات والأوامر؛ لا يحتوي بيانات اعتماد.
- `packages/domain`: انتقالات حالات مستقلة عن HTTP وقاعدة البيانات، مع ساعة صريحة للاختبار.
- `packages/database`: ترحيل PostgreSQL ومستودع معاملات؛ جداول منفصلة للكيانات، مع JSONB للحقول المتطورة وأعمدة علائقية وقيود لفترات إسناد الطاولات.
- `apps/edge-api`: مصادقة الجلسات والصلاحيات، تنفيذ الأوامر، عامل المهلات، وواجهة HTTP المحلية.
- `apps/web`: واجهة عربية RTL، حاليًا بتحديث دوري، مع تعطيل الإجراءات عند فقد الاتصال.

السحابة لم تُنفذ بعد. توجد خدمة اختيارية `apps/vision-lab` لتقرير فيديو مسجل على CPU، تُمرّر طلباتها عبر API المالك؛ لا تتصل بمستودع المجال ولا تنشئ أحداثًا تشغيلية. انظر [دليل التجربة](../operations/recorded-video-trial.md). `synchronization_outbox` يحفظ أحداثًا في حالة QUEUED فقط؛ وجوده لا يعني تسليم حدث أو دفع إشعار.

## المعاملات ومنع التكرار

تُقفل سطرية المطعم أثناء كل تعديل. هذا يبسّط ضمان مصدر حقيقة واحد في الإصدار الأول ويمنع سباق الإقرارات والتعيينات. تُقرأ الحالة، تُطبق قواعد المجال، وتُحفظ الحالة والأحداث وصندوق الإرسال وسجل العملية داخل معاملة واحدة.

لكل أمر `commandId` فريد وبصمة تربط الأمر بالفاعل. إعادة نفس الطلب تعيد `replayed=true` دون تطبيق آخر. إعادة المعرف بمحتوى أو فاعل مختلف تُرفض. تعديلات الطاولات والجلسات والمهام تتطلب الإصدار المتوقع. أول تعيين لمصدر المهمة يتطلب الإصدار صفرًا.

تدعم قيود PostgreSQL جلسة نشطة واحدة لكل طاولة، وعدم تداخل فترات إسنادها، ودورة تنظيف مفتوحة واحدة، ومهمة واحدة لكل مصدر ونوع، وتنبيهًا واحدًا لكل مفتاح منع تكرار.

## الوقت والاستعادة

الأوقات محفوظة بصيغة UTC وتُعرض بتوقيت المتصفح. المؤقت مشتق من وقت بداية الجلسة أو دورة التنظيف وليس عدادًا يزداد في الذاكرة. عند بدء عامل الخادم تُسجل فترة منذ آخر heartbeat كفجوة غير متحقق منها، وتصبح حالة الرؤية UNKNOWN دون إغلاق جلسة أو إلغاء تصحيح يدوي.

أوقات الملاحظة الأصلية منفصلة عن الأوقات المعتمدة وتعديلات المدير. الحماية اليدوية لا تنتهي تلقائيًا بعد 60 ثانية: يلزم انتقال رؤية موثوق جديد بدأ بعد انتهاء الحماية؛ الأدلة القديمة واستعادة الرؤية وحدها لا تكفيان.

محاكي الأحداث يستقبل انتقالات متحققة مسبقًا، لا صورًا خامًا. التحقق من مدد 5/30 ثانية ضمن عقد المحاكي لا يمثل تنفيذ الرؤية الزمنية أو دمج الكاميرات الفعلي. اختبار تكرار الأحداث يثبت منع تكرار الحالة التشغيلية، ولا يثبت جودة دمج الأدلة البصرية.

## الصلاحيات والخصوصية

الحسابات تستخدم scrypt بكلمة ملح عشوائية، وجلسات عشوائية محفوظة في قاعدة البيانات كبصمات، وcookie من نوع HttpOnly وSameSite Strict. المصدر المشترك وطلبات JSON والتحقق من Origin وSec-Fetch-Site تحد من CSRF؛ تسجيل الدخول محدود المعدل.

يتحقق كل مسار مطعم من العضوية. لا يحصل النادل من dashboard على تنبيهات المدير أو سجل التدقيق أو جلسات الضيوف أو تفاصيل زملائه ومحاولاتهم السابقة. المهام المعاد إسنادها تختفي من قائمة النادل القديم، والخادم يرفض إجراءاته حتى لو احتفظ بمعرفها.

سجلات التدقيق والأحداث وتعديلات الوقت وفجوات المراقبة تمنع التعديل والحذف عبر triggers وتُضاف فقط عبر المستودع. هذا لا يحمي من مدير قاعدة بيانات قادر على تغيير المخطط أو تعطيل triggers؛ يجب استخدام دور تشغيل محدود الصلاحيات وفصل مالك المخطط قبل الإنتاج.

## الحدود الحالية

يحمّل المستودع تاريخ مطعم كاملًا داخل المعاملة؛ هذا مناسب لبداية وظيفية محدودة الحجم، ويجب إضافة pagination وقراءات مستهدفة وسياسة احتفاظ قبل الاختبار طويل المدى. لا توجد بعد دورة استعادة كلمة مرور أو تعطيل الحسابات أو تشفير أسرار الكاميرات أو دعم دون اتصال على متصفح الهاتف. عمل الخادم المحلي دون WAN يختلف عن قدرة المتصفح على تنفيذ إجراء حين لا يصل للخادم.

في مرحلة السحابة: اتصال مشفر يبدأ من الخادم المحلي، مع معرفات أحداث وتسلسل وإصدارات وعقود مصالحة. لا نجاح نهائي لأوامر النسخة البعيدة قبل اعتماد السلطة المحلية. لا نستخدم تعارضات last-write-wins للحالة التشغيلية.
